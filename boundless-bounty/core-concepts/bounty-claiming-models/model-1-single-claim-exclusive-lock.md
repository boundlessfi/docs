# Model 1 — Single Claim (exclusive lock)

First contributor to claim gets the bounty.

The bounty stays locked until completion or release.

### Best used for

* Urgent fixes.
* Clear scope.
* Maintenance tasks.
* Smaller budgets.

### Workflow

1. Project posts bounty as **Open**.
2. First contributor clicks **Claim**.
3. Status becomes **Claimed** and locks to that wallet.
4. Contributor submits deliverable.
5. Project approves or rejects.
6. Approval releases payment.
7. Rejection can reopen the bounty.

### Anti-squatting rules

* Auto-release if no submission within **7 days**.
* Auto-release if no response to feedback within **3 days**.
* Abandonment impacts reputation.
* Projects can manually unclaim with a reason.

{% hint style="warning" %}
Single Claim optimizes for speed. It does not optimize for “best submission”.
{% endhint %}
